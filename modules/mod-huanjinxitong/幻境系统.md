# 幻境系统倍率计算修复说明

## 问题描述

幻境系统的生物属性倍率计算存在严重错误，导致指数增长而不是线性增长：

- 原本护甲：10673
- 2倍属性：42692（应该是21346，但实际约4倍）
- 3倍属性：384228（应该是32019，但实际约36倍）
- 4倍属性：6147648（应该是42692，但实际约576倍）

## 问题根源

1. **重复调用导致指数增长**：`AdjustCreatureStats` 函数被多次调用，每次都在已经调整过的属性基础上再次应用倍率
2. **基础值获取错误**：获取的 `BASE_VALUE` 可能已经是被修改过的值，而不是真正的原始值
3. **倍率公式错误**：使用了 `5.0f + huanJingLevel` 这样的公式，导致倍率过高

## 修复方案

### 1. 修正倍率计算公式

**修复前：**

```cpp
float levelMultiplier = 5.0f + huanJingLevel; // 1级=6倍，2级=7倍，3级=8倍...
```

**修复后：**

```cpp
float levelMultiplier = 1.0f + huanJingLevel; // 1级=2倍，2级=3倍，3级=4倍，4级=5倍...
```

### 2. 使用真正的原始属性值

**修复前：**

```cpp
float originalHealth = creature->GetModifierValue(UNIT_MOD_HEALTH, BASE_VALUE);
```

**修复后：**

```cpp
const CreatureTemplate* cInfo = creature->GetCreatureTemplate();
CreatureBaseStats const* stats = sObjectMgr->GetCreatureBaseStats(creature->GetLevel(), cInfo->unit_class);
uint32 originalHealth = uint32(stats->BaseHealth[EXPANSION_WRATH_OF_THE_LICH_KING] * cInfo->ModHealth);
```

### 3. 增强状态清理

**新增：**

```cpp
// 清除幻境系统的调整标记，防止重复调整
uint64 creatureKey = GenerateCreatureKey(creature);
_creatureAdjustedLevels.erase(creatureKey);

// 清除法术强度记录
ClearCreatureSpellPower(creature);

// 移除专精光环
creature->RemoveAurasByType(SPELL_AURA_MOD_EXPERTISE);
```

### 4. 添加详细日志

**新增调试日志：**

```cpp
LOG_DEBUG("module", ">> 生物 {} 血量调整: 原始={}, 倍率={:.1f}, 调整后={}",
          creature->GetEntry(), originalHealth, levelMultiplier, adjustedHealthValue);
```

## 预期效果

修复后，幻境系统的倍率计算应该是线性的：

- 幻境等级1：2倍属性
- 幻境等级2：3倍属性
- 幻境等级3：4倍属性
- 幻境等级4：5倍属性

例如，原本护甲10673的生物：

- 2倍属性：21346
- 3倍属性：32019
- 4倍属性：42692

## 影响范围

此修复影响以下属性的倍率计算：

- 血量（Health）
- 法力（Mana）
- 护甲（Armor）
- 攻击强度（Attack Power）
- 伤害（Damage）
- 法术强度（Spell Power）

## 注意事项

1. 修复后需要重新编译模块
2. 建议在测试服务器上先验证效果
3. 现有已调整的生物会在下次触发调整时自动修复
4. 配置文件中的倍率设置也会使用正确的基础值计算


# 幻境系统技术说明

## 1. 模块概览
- 目标：按地图/区域/生物配置动态放大生物属性、支持多血条、控制掉落倍率与鉴定集成、对玩家装备施加幻境增强，并提供性能节流与数据清理。
- 主要文件：`src/HuanJingSystem.h/.cpp`；配置表：`_模板_地图生物控制`；装备增强存储：`玩家装备属性增强`。

## 2. 核心流程
### 初始化
- `HuanJingSystem::Initialize`：加载生物倍率/性能与上限配置，启动定期装备清理 `ScheduleItemCleanup()`。

### 玩家侧
- 登录：`OnPlayerLogin` 加载装备增强数据，分批（事件队列）对需要的装备调用 `ApplyHuanJingEnhancement(updateStats=false)`，末尾统一 `UpdateAllStats` 并清理未装备增强。
- 在线更新：`OnPlayerUpdate / ScheduleAdjustNearbyCreaturesAsync` 按移动状态和批次异步调整附近生物。
- 登出：清理缓存、根据剩余玩家重算附近生物。
- 装备：`OnPlayerEquip` 登录阶段跳过，进世界后对有增强/倍率的装备调用 `ApplyHuanJingEnhancement`; `OnPlayerCanUnequipItem` 预移除增强；`CleanupUnequippedItemEnhancements` 防止叠加。

### 生物侧
- 调整：`AdjustCreatureStats` 基于地图/区域/生物配置倍率重置并放大血量/法力/伤害/护甲/攻强/移速等，可触发血条系统；`AdjustCreatureStatsForPlayer/WithHighestLevel` 按场景复用；重生/副本重置通过 `_creatureAdjustedLevels` 记录与还原。
- 血条：`InitializeCreatureHealthBars` 建立多条血；`HandleUnitKill` 拦截致死按条扣血；`BroadcastHealthBarUpdateThrottled` 节流广播到客户端 Addon。
- 上限保护：`ClampCreatureHealthToMax / EnsureCreatureHealthSafe` 将过高血量折算为血条，避免溢出。

### 掉落与鉴定/成长集成
- 死亡：`RecordCreatureDeathHuanJingLevel` 记录击杀环境，避免拾取漏洞。
- 拾取：`OnPlayerLootItem` 仅处理武器/护甲，按地图配置计算倍率，写入装备增强存档并可设置鉴定组 (`identificationGroup`)；未调整的生物不掉倍率装备。
- 物品成长：若开启 `MODULE_ITEM_GROWTH`，通过鉴定系统批量接口获取成长属性（条件编译）。

### 数据清理与维护
- `ScheduleItemCleanup/CleanupInvalidItems` 定期清孤儿 `item_instance`。
- 缓存容器均有互斥保护：物品增强、生物调整、血条数据、恢复队列等。

## 3. 配置与表
- 地图路由表（World DB）：`_模板_地图生物控制` 只保存生物/类型/地图/区域/难度匹配、`生物控制组`、刷新公告/刷新时间和动态难度。
- 属性模板表（World DB）：`__模版生物属性表` 保存血量、法力、伤害、护甲、抗性、攻强/法强、速度、穿透、血条、掉落、装备倍率和鉴定配置。
- 随机控制组（World DB）：`_生物控制组表` 将一个组号关联到一个或多个属性模板，并可同时随机模型、大小和武器。每只生物首次解析后固定结果，战斗和动态难度重算不会再次随机。
- 旧 `_生物属性控制表`、`_地图生物属性控制` 和 `_地图区域生物属性表` 已淘汰并删除，地图生物配置统一使用 `_模板_地图生物控制`。
- 装备增强表（Characters DB）：`玩家装备属性增强` 保存装备倍率与属性增强数据。
- 性能/上限配置（worldserver.conf）：
  - `HuanJingSystem.CheckInterval.Moving/Stopped/Idle`
  - `HuanJingSystem.MovementThreshold`
  - `HuanJingSystem.BatchSize`
  - 上限类：`HuanJingSystem.MaxHealth/MaxDamage/MaxArmor/MaxAttackPower/MaxResistance/MaxMana/MaxSpellPower/MaxCritChance/MaxHitChance/MaxHaste/MaxExpertise/MaxDodgeChance/MaxParryChance/MaxBlockChance/MaxMovementSpeed`
- 鉴定集成：`__模版生物属性表.鉴定组` + 拾取时写入 `item_attribute_enhancement.identificationGroupId`。

## 4. 已知问题（需优先修复）
1) **伤害上限默认为 0 导致全局伤害被压成 0**
   - 原因：`_maxDamageValue` 缺省取 0，后续 `std::min(..., _maxDamageValue)`。
   - 影响：缺省配置下所有生物伤害为 0。
   - 建议：0 视为“无限制”，使用明确的安全上限（如 2.1e9f）；计算前设 `damageCap = _maxDamageValue > 0 ? _maxDamageValue : defaultCap`。

2) **配置调整等级后仍用旧等级基值计算，倍率失真**
   - 原因：`AdjustCreatureStats` 先取 `stats`，再可能重设等级，但后续血量/伤害/护甲等继续用旧 `stats`。
   - 影响：按配置等级放大失真，属性偏低/错误。
   - 建议：重设等级后重新获取 `CreatureBaseStats` 基于新等级再算倍率。

3) **玩家数据返回裸指针存在悬空/竞争风险**
   - 原因：`GetPlayerData` 在锁内取地址，解锁后返回指针。
   - 影响：并发擦除/重排可能导致悬空或数据竞争。
   - 建议：返回值改拷贝/optional，或提供带锁访问回调；避免返回内部指针。

## 5. 优化建议
- 上限默认值一致性：所有上限配置 0 时采用统一安全默认值，加载时一次性告警。
- 模块拆分：按领域拆成多个 cpp（配置加载、生物调整、血条、装备增强、命令/GM 工具、清理维护），降低单文件复杂度。
- 线程安全封装：为玩家/生物/物品容器提供只读/写入封装接口，消除裸指针模式；缩短锁粒度，避免跨回调持锁。
- 血条同步体验：致死拦截后立即广播一次；脱战/消失时做最终同步，减少客户端滞后。
- 日志与告警：上限命中、配置缺失、表缺失时只输出一次警告；将性能关键路径的 DEBUG 级别可控开关化。
- 性能：保持分批事件处理；高负载时可调低 `_batchSize`、拉长检查间隔。

## 6. 典型运维/使用要点
- 确保配置表存在并填充；无表则功能受限。
- worldserver.conf 建议显式配置伤害等上限，避免默认 0。
- Addon 前缀 `HBUI`，血条显示需客户端插件订阅。
- 鉴定组：在 `__模版生物属性表` 设置 `鉴定组`，再通过 `_生物控制组表` 关联到地图路由；未被地图系统调整的生物不会掉倍率/鉴定物品。
